# Дом рядом

**Дом рядом — помощь у порога.**

Прототип мини-приложения для жителей многоквартирных домов. Житель выбирает дом, описывает проблему и получает заявку с номером, а диспетчер управляет заявками в закрытой панели. Проект разрабатывается для запуска в виде мини-приложения MAX.

## Что уже работает

**Жителю:**

- выбор дома и категории проблемы;
- описание ситуации с проверкой заполненных данных;
- определение ответственной службы и подсказка о дальнейших действиях;
- копирование готового текста обращения;
- создание заявки с автоматическим номером вида `REQ-000001`;
- адаптивный интерфейс для телефона.

**Диспетчеру (панель закрыта паролем):**

- список заявок с поиском по номеру и описанию;
- фильтр по статусу, сортировка по номеру и дате, переключение порядка;
- свободная смена статуса без жёсткой лестницы переходов;
- обязательная причина только при отказе;
- история смены статусов с автором, временем и сохранённой причиной;
- поиск и фильтры сохраняются в адресе страницы, поэтому ссылку можно переслать коллеге.

**Хранение:**

- PostgreSQL, заявки переживают перезапуск сервера;
- журнал смены статусов пишется в той же транзакции, что и сам статус;
- миграции накатываются автоматически на пустой базе.

## Требования

- Docker и Docker Compose — проще всего;
- либо Go 1.27+ и PostgreSQL, если запускать без Docker.

## Запуск через Docker Compose

```bash
git clone https://github.com/jadoreblessed/dom-ryadom.git
cd dom-ryadom
cp .env.example .env
```

Сгенерируйте ключ подписи сессий и впишите его в `.env`:

```bash
openssl rand -hex 32
```

Затем запустите:

```bash
docker compose up -d --build
docker compose logs app
```

При первом запуске пароль диспетчера **генерируется случайно и печатается в лог один раз**:

```text
создан диспетчер "dispatcher", пароль сгенерирован: <ваш пароль>
```

Сохраните его: в базе лежит только хеш, восстановить пароль нельзя. Узнать его позже можно только удалив учётную запись и перезапустив приложение.

| Адрес | Кто видит |
|---|---|
| `http://localhost:8080/app` | форма подачи заявки жителем |
| `http://localhost:8080/login` | вход диспетчера |
| `http://localhost:8080/admin` | панель заявок, требует входа |
| `http://localhost:8080/health` | проверка работы сервера |

### Пароль из `.env`

Переменной `DISPATCHER_PASSWORD` в `.env` нет намеренно. Если её задать, приложение возьмёт пароль оттуда, но он перестанет действовать при пересоздании базы. Заглушка вида `change-me` опаснее её отсутствия: она одинаково подходит всем, кто её видел, а `.env` рано или поздно уезжает в репозиторий или в архив.

`AUTH_SECRET` обязателен и не короче 32 символов. С более коротким приложение не стартует: такую подпись можно подобрать перебором и выпустить сессию от чужого имени.

## Запуск без Docker

```bash
go run .
```

Нужны переменные `DATABASE_URL`, `DISPATCHER_LOGIN`, `AUTH_SECRET`, `PORT`. Миграции в этом режиме накатываются вручную, по порядку:

```bash
for f in migrations/*.sql; do psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f "$f"; done
```

## Статусы заявок

Четыре статуса, `GET /statuses` отдаёт их список и отдельно закрытые:

| Статус | Закрытый | Смысл |
|---|---|---|
| `Новая` | нет | заявка принята, диспетчер ещё не взял |
| `В работе` | нет | назначена ответственному |
| `Выполнена` | да | работа закончена |
| `Отклонена` | да | отказ, причина обязательна |

Заявку можно вернуть в работу из любого состояния — в том числе из закрытого, по кнопке «Изменить статус». Единственный запрещённый переход — в тот же статус, он отклоняется с `400` и текстом «Статус заявки не изменился»: молчаливый отказ трудно понять.

Причина обязательна только для `Отклонена` и сохраняется в журнале вместе со сменой статуса, поэтому не теряется, когда следующим действием статус меняют снова.

## Доступ к данным

Закрыты и требуют сессии диспетчера:

- `GET /admin`;
- `GET /requests` — список всех заявок всех жителей;
- `GET /requests/{number}`;
- `GET /requests/{number}/history`;
- `PATCH /requests/{number}/status`;
- `GET /auth/me`.

Открыты всем, включая подачу заявки: `/app`, `/login`, `/statuses`, `/categories`, `/buildings`, `/requests/preview`, `POST /requests`, `/health`.

Пароли хранятся как `PBKDF2-HMAC-SHA256`, 600 000 итераций, соль на пользователя, число итераций записано внутрь хеша. Сессия — подписанная cookie `HttpOnly` и `SameSite=Lax` на 12 часов. Неверный логин и неверный пароль дают одинаковый ответ и одинаковое время ответа, чтобы по времени нельзя было перебирать логины. Учётная запись создаётся один раз и не перетирается при каждом перезапуске.

## API

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/health` | открыт | проверка работы сервера |
| `GET` | `/categories` | открыт | категории проблем |
| `GET` | `/buildings` | открыт | список домов |
| `GET` | `/statuses` | открыт | статусы и закрытые статусы |
| `POST` | `/requests/preview` | открыт | предварительная проверка обращения |
| `POST` | `/requests` | открыт | создание заявки |
| `GET` | `/app` | открыт | интерфейс жителя |
| `GET` | `/login` | открыт | вход диспетчера |
| `POST` | `/auth/login` | открыт | вход, ставит cookie |
| `POST` | `/auth/logout` | открыт | выход, снимает cookie |
| `GET` | `/admin` | сессия | панель диспетчера |
| `GET` | `/auth/me` | сессия | логин текущего диспетчера |
| `GET` | `/requests` | сессия | список заявок |
| `GET` | `/requests/{number}` | сессия | заявка по номеру |
| `GET` | `/requests/{number}/history` | сессия | история смены статусов |
| `PATCH` | `/requests/{number}/status` | сессия | смена статуса |

`GET /requests` принимает `q`, `status`, `sort` (`number`, `created_at`, `updated_at`) и `order` (`asc`, `desc`), а также `limit`.

### Создание заявки

```json
{
  "building_id": "house-1",
  "category": "Протечка",
  "description": "Течёт труба в подъезде"
}
```

Ответ `200`:

```json
{
  "id": "REQ-000001",
  "number": "REQ-000001",
  "request": {
    "category": "Протечка",
    "address": "ул. Лесная, д. 5",
    "description": "Течёт труба в подъезде",
    "building_id": "house-1"
  },
  "managing_org": "Тестовая УК №1",
  "responsible": "Аварийно-диспетчерская служба",
  "next_step": "Свяжитесь с аварийно-диспетчерской службой вашего дома и сообщите адрес и место протечки.",
  "status": "Новая",
  "comment": "",
  "created_at": "2026-09-28T19:57:29Z",
  "updated_at": "2026-09-28T19:57:29Z"
}
```

### Смена статуса

```json
{ "status": "Отклонена", "comment": "Не входит в зону ответственности" }
```

### История заявки

```json
[
  {
    "from_status": "Новая",
    "to_status": "В работе",
    "changed_by": "dispatcher",
    "comment": "",
    "changed_at": "2026-09-28T19:30:49Z"
  }
]
```

`changed_by` — логин вошедшего диспетчера, а у первой записи всегда `resident`.

## Структура проекта

```text
dom-ryadom/
├── main.go            запуск сервера и HTTP-маршруты
├── config.go          чтение переменных окружения
├── db.go              подключение к PostgreSQL
├── store.go           запросы к заявкам, транзакции
├── requests.go        типы заявок
├── status.go          статусы, смена статуса, запись в журнал
├── history.go         чтение и запись истории
├── auth.go            вход, сессии, хеширование паролей
├── filter.go          поиск, фильтры, сортировка
├── routing.go         определение ответственной службы
├── buildings.go       тестовые дома и управляющие организации
├── errors.go          единый формат ошибок
├── migrations/        SQL-миграции, накатываются по порядку
├── deploy/            сертификаты для внешних API
├── web/
│   ├── index.html     интерфейс жителя
│   ├── admin.html     панель диспетчера
│   └── login.html     вход
└── compose.yaml
```

## Миграции

| Файл | Что делает |
|---|---|
| `001_init.sql` | таблицы домов, заявок, диспетчеров |
| `002_seed.sql` | тестовые дома и управляющие организации |
| `003_request_comment.sql` | колонка `comment` в заявках |
| `004_backfill_history.sql` | журнал для заявок, созданных до его появления |

Новую миграцию кладите рядом и наращивайте номер: файлы применяются по порядку при первом запуске на пустой базе.

## Что планируется добавить

- получение кода жителем в MAX для отслеживания своей заявки;
- уведомление жителю о смене статуса;
- дедупликация: не создавать вторую карточку на ту же проблему того же жителя;
- способ сменить пароль диспетчера из интерфейса;
- реальные дома и управляющие организации вместо тестовых;
- размещение под HTTPS.

Интеграция с MAX ещё не написана. В образе уже закреплён сертификат Минцифры: без него API MAX недоступен, TLS-рукопожатие падает с `certificate signed by unknown authority`. Работает это только на `platform-api2.max.ru`; писать жителю можно лишь в диалог, который он сам открыл с ботом, — отправить сообщение по номеру телефона API не позволяет.
